① 系統鳥瞰：三層 + 兩個外部朋友

整個 app 是三層疊起來的：Tauri 外殼（Rust，負責桌面 app 該有的東西）、Next.js 引擎（app 真正的大腦與畫面）、本機資料（你的 vault + app 私有 JSON）。外殼幾乎不做事，它只是把引擎包成可以雙擊的 .app。圖上每塊可點，會跳到對應的深度展開。

② 啟動旅程：從雙擊到儀表板

關鍵設計：外殼和引擎是兩個獨立程式，用一張每次啟動都重新鑄造的「一次性通行證（token）」互相認親 —— 所以你電腦上其他程式無法假裝成 Yen Hub。

  1. 你雙擊 Yen.appsrc-tauri/src/lib.rs

    Tauri 醒來：開視窗、掛 plugins（通知/日誌/shell）、先顯示白色呼吸動畫（splash）。

  2. 開門前準備src-tauri/src/sidecar.rs

    選一個沒人用的 port、鑄造 32 byte 隨機 token、從 ~/.config/yen-hub/env 讀 API key、確保 session 密鑰存在（session.key，權限 0600）。

  3. 啟動 Node.js 引擎sidecar.rs → server.js

    spawn 子進程跑 Next.js 伺服器，把 PORT、token、API key、vault 路徑用環境變數塞進去；同時監聽引擎的 stdout（[NOTIFY] 行會轉成原生通知）。

  4. 等引擎開門wait_until_ready()

    每隔一下戳 localhost:port，最多等 20 秒，活了才繼續。

  5. 視窗帶 token 進門app/page.tsx · lib/security/sidecar-token.ts

    webview 載入 http://127.0.0.1:port/?_yt=token；頁面把 token 收進 sessionStorage、立刻清掉網址，之後每個 API 請求自動帶 X-Yen-Token header。

  6. 門口檢查哨middleware.ts

    所有 /api/* 請求都被攔下來驗 token，不對就 403。auth 和 diag 路由免檢。

  7. Touch ID 點頭放行app/page.tsx · lib/auth/

    Tauri 裡走原生 Touch ID，瀏覽器裡走 WebAuthn passkey，通過後跳轉 /hub 儀表板。

  8. 隱藏動作：掛四個鬧鐘instrumentation.ts

    引擎啟動同時掛起：週日晚提案週摘要、檢查放太久的承諾、執行你排的提醒、輪詢 Telegram。這是 app 開著時 Duffy 會「自己動」的原因。

③ Duffy 迴圈：讀的直接做，寫的先開卡

整個系統最核心的設計。Duffy 的工具分兩類：read_*（讀，無副作用，隨便用）和 propose_*（寫，只能開一張 intent 提案卡，等你批准才生效）。

read_* 讀取工具全清單（無副作用）lib/agent/duffy/tools.ts 等
工具白話
read_attention_state看你最近 7 天注意力花在 vault 哪些區
read_todos看 Queue 裡的待辦清單
read_observations_history / search_observations翻、搜過去記下的觀察
search_old_summaries搜舊的週摘要
search_vault / read_vault_file全庫搜尋、讀單篇筆記
read_conversation_history翻你們的舊對話
web_search / web_extract搜網路、抓網頁內容
list_external_dir / read_external_file看 Develop 與 Learning_AI 資料夾（唯讀）
list_skills / use_skill瀏覽並載入你的 skill 庫
git_status 等白名單命令沙箱裡跑幾個安全的開發指令
list_pending_intents看自己還有哪些提案在等你批
propose_* 提案工具全清單（產生 intent 卡）vault-write-tools.ts 等
工具提案內容
propose_observation記一條對你的觀察（含證據與理由）
propose_silhouette_update更新剪影的某個欄位（身份/風格/價值/邊界/優先）
propose_todo建議加一條待辦進 Queue
propose_new_file / propose_edit_file建議建新筆記、改舊筆記

信任分層與自動駕駛trust-config.ts · auto-pilot.ts
層例子「平衡」模式下
L0 低風險寫一條觀察自動執行，24h 內可撤銷
L1 中建新檔、新排程、週摘要跳一張審批卡
L2 不可逆改既有檔、更新剪影永遠要你批

三檔模式：謹慎（全要批）／平衡（L0 自動）／奔放（L0+L1 自動），預設謹慎。每次 approve/reject 都被記成訊號，通過率 ≥90% 時 Duffy 會主動提議升級；Auto-pilot 開啟後它自己升降 tier，每次調整寫 audit log。批准後由 intent-materialize.ts 執行副作用、vault-bridge.ts 鏡像到 vault。

Duffy 還有四種工作模式前綴：[coach] 反思（只讀）、[do] 執行（可提案）、[watch] 觀察（只列狀態）、[pair] 協作（一步一報）。定義在 prompt.ts。

④ 資料地圖：JSON 是正本，vault 是鏡像

Duffy 的記憶存在兩個地方，而且方向不對稱：app 私有 JSON 是正本，vault 的 06 - AI Data/ 是批准後才鏡像過去的副本 —— 這就是那三個資料夾「人類不該手動編輯」的原因。

→ 讀取：app 掃描 vault（待辦、注意力、SOUL）　｜　← 鏡像：批准的觀察/剪影/週摘要寫回 vault

Obsidian Vault（你每天看的）

  • 05 - Queue/ — 待辦與草稿；todos.ts 掃描、勾掉用 overlay 不直接改檔
  • 06 - AI Data/Observations/ — 批准的觀察，按月份資料夾存 md
  • 06 - AI Data/Silhouettes/ — 剪影現版 + 歷史版本
  • 06 - AI Data/Summaries/ — 週摘要，ISO 週編號
  • 06 - AI Data/agents/duffy.md — SOUL 人格定義；你可以編輯，app 會同步回來
  • 其他筆記區 — reader.ts 分成八個 zone 算注意力；.obsidian/workspace.json 提供「最近開過哪些檔」

App 私有資料 ~/Library/…/com.yen.hub/

  • intents.json — 所有提案卡與審批紀錄（pending/approved/rejected）
  • observations.json / silhouettes.json / summaries.json — Duffy 記憶的正本
  • conversations — 聊天歷史
  • coach.json — 教練卡快取（1 小時）；批准任何記憶類 intent 時清掉重算
  • done.json / priority — 待辦完成與優先標記（覆蓋層）
  • session.key — 登入 cookie 的簽章鑰匙
  • trust-config · auto-pilot log · schedules · telegram-chats — 信任、審計、排程、白名單
